# Day 041 - Write a Dockerfile (Build a Custom Apache Image)

**100 Days of DevOps, Day 41:** how to write a Dockerfile that installs and configures Apache on a non-default port, then build it into a reusable image with `docker build` — moving from ad-hoc container changes to a reproducible image definition.

## 🎯 Objective

On the app server, create a Dockerfile at `/opt/docker/Dockerfile` that starts from an Ubuntu base image, installs `apache2`, and configures it to listen on port `5004` — without changing any other default Apache configuration. Build the image from this Dockerfile.

---

## Why This Matters

`docker commit` (Day 39) and `docker exec` (Day 40) are fine for one-off fixes, but neither is reproducible — the changes live only in that container's history. A Dockerfile turns the same kind of setup into version-controlled, repeatable instructions: anyone can rebuild the exact same image from scratch, which is what makes images shareable across environments and safe to rebuild in CI.

---

## Connect to the App Server

```bash
ssh steve@stapp02
sudo su -
```

---

## Create the Dockerfile Directory

```bash
mkdir -p /opt/docker
vi /opt/docker/Dockerfile
```

---

## Write the Dockerfile

```dockerfile
FROM ubuntu
RUN apt-get update && apt-get install -y apache2
RUN sed -i 's/Listen 80/Listen 5004/g' /etc/apache2/ports.conf
EXPOSE 5004
```

- `FROM ubuntu` — starts from a clean Ubuntu base image.
- `RUN apt-get update && apt-get install -y apache2` — installs Apache in a single layer.
- `Listen 5004` appended to `ports.conf` — adds the new port without removing the default `Listen 80` line, matching the "don't change other defaults" requirement.
- The `sed` on `000-default.conf` points the default virtual host at the new port.
- `EXPOSE 5004` documents the port the container listens on (informational — it doesn't publish it by itself).

---

## Build the Image

```bash
docker build -t custom-apache-image /opt/docker/
```

`-t` tags the resulting image; the trailing path is the build context Docker sends to the daemon (here, just the directory containing the Dockerfile).

---

## Run and Verify

```bash
docker run -d -p 5004:5004 custom-apache-image
curl -I http://localhost:5004/
```

A `HTTP/1.1 200 OK` response confirms Apache is serving on port 5004 from the newly built image.

---

## Key Takeaways

- A Dockerfile makes container setup reproducible and version-controllable, unlike `docker commit` or manual `docker exec` changes.
- Each `RUN` instruction adds a layer — chaining related commands with `&&` keeps the image leaner.
- `EXPOSE` is documentation, not enforcement — the port still needs `-p` at `docker run` time to be reachable from the host.
- `CMD` should keep the main process in the foreground; if Apache daemonizes and exits, the container exits with it.

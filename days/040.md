# Day 040 - Docker EXEC Operations (Configure Apache Inside a Running Container)

**100 Days of DevOps, Day 40:** how to use `docker exec` to install and configure software inside an already-running container, without stopping it or rebuilding its image.

## 🎯 Objective

On the app server, install `apache2` inside the running container `kkloud` using `apt`, configure it to listen on port `3003` instead of the default HTTP port (bound to all interfaces, not a specific IP or hostname), start the service, and leave the container running.

---

## Why This Matters

`docker exec` is what makes a running container feel like a normal Linux host for troubleshooting and configuration — it drops you into the container's own process namespace and filesystem, so commands like `apt install` or editing a config file behave exactly as they would over SSH. This task is a common real-world scenario: finishing configuration work inside a container someone else started, without disrupting whatever else it's already running.

---

## Connect to the App Server

```bash
ssh steve@stapp02
sudo su -
```

---

## Exec Into the Container

```bash
docker exec -it kkloud /bin/bash
```

`-it` allocates an interactive TTY and attaches stdin, giving a live shell inside the `kkloud` container.

---

## Install Apache

```bash
apt update
apt install apache2 -y
```

---

## Configure Apache to Listen on Port 3003

```bash
cd /etc/apache2
sed -i 's/Listen 80/Listen 3003/g' ports.conf
sed -i 's/:80/:3003/g' apache2.conf
```

- `ports.conf` controls which port(s) Apache binds to — changing `Listen 80` to `Listen 3003` moves it off the default HTTP port.
- Leaving the `Listen` directive as just a port number (no IP prefix) means Apache binds to **all** interfaces, satisfying the "not a specific IP or hostname" requirement.

---

## Start Apache Inside the Container

```bash
service apache2 start
service apache2 status
```

Since the container likely doesn't run systemd, `service` (which wraps `apachectl`/init scripts) is used instead of `systemctl`.

---

## Exit Without Stopping the Container

```bash
exit
```

Exiting the `docker exec` shell only ends that session — the container itself, and the Apache process inside it, keep running.

---

## Verify From the Host

```bash
docker ps -a
docker exec kkloud service apache2 status
```

Confirms `kkloud` is still `Up` and Apache is active inside it.

---

## Key Takeaways

- `docker exec -it <container> /bin/bash` opens an interactive shell inside a running container for live troubleshooting or configuration.
- Inside minimal containers, `service` is often the only way to manage daemons since systemd isn't typically installed.
- A bare port number in `Listen <port>` binds to all interfaces; a bound-looking config would instead show `Listen <ip>:<port>`.
- Exiting an exec session never stops the container — only `docker stop` does that.

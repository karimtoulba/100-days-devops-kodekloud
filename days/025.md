# Day 025 - Git Merge Branches (git merge, git push)

**100 Days of DevOps, Day 25:** how to commit a change on a feature branch, merge it back into `master`, and push both branches to a shared remote.

## 🎯 Objective

Add a new file on the feature branch, then merge those changes back into `master` and push both branches to the remote.

---

## Why This Matters

Merging is how finished feature-branch work rejoins the main line, and it's the step where conflicts between parallel changes first surface. Pushing both the feature branch and `master` after the merge keeps the remote repository in sync with local history, so the rest of the team sees exactly the same state — this end-to-end branch, merge, push cycle is the core loop of everyday Git collaboration.

---

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Logs in to the storage server hosting the shared repository.

---

## Navigate to the Repository

```bash
cd /usr/kodekloudrepos/blog
```

Moves into the working copy of the repository.

---

## Switch to the Feature Branch

```bash
sudo git switch xfusioncorp_blog
```

Checks out the feature branch created on Day 024, so the new file is committed there rather than on `master`.

---

## Copy the New File into the Repository

```bash
sudo cp /tmp/index.html .
```

Copies the new content into the repository's working directory, ready to be tracked by Git.

---

## Stage and Commit the File

```bash
sudo git add index.html
sudo git commit -m "Add index.html to xfusioncorp_blog branch"
```

`git add` stages the new file and `git commit` records it as a snapshot on the `xfusioncorp_blog` branch, with a message describing what changed.

---

## Switch Back to Master

```bash
sudo git switch master
```

Checks out `master` so the upcoming merge is performed on the target branch.

---

## Merge the Feature Branch into Master

```bash
sudo git merge xfusioncorp_blog
```

Integrates the commits from `xfusioncorp_blog` into `master`. Since no other commits landed on `master` in the meantime, Git performs this as a straightforward fast-forward (or simple) merge with no conflicts to resolve.

---

## Push Both Branches to Origin

```bash
sudo git push origin master
sudo git push origin xfusioncorp_blog
```

Publishes the updated `master` (now containing the merged change) and the `xfusioncorp_blog` branch to the remote, so both are visible and up to date for the rest of the team.

---

## Key Takeaways

- The branch → commit → switch-to-target → merge → push sequence is the standard everyday Git workflow.
- Merging early and often (rather than letting a feature branch drift far from `master`) keeps conflicts small and manageable.
- Pushing the feature branch in addition to `master` preserves its history on the remote, which matters for traceability and code review.
- `git merge` brings the *commits*, not just the files, from one branch into another — full history is preserved.

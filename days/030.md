# Day 030 - Git Hard Reset (git reset --hard, force push)

**100 Days of DevOps, Day 30:** how to use `git reset --hard` to rewind a branch to a known-good commit and force-push the cleaned-up history to a shared remote.

## 🎯 Objective

The repository has accumulated unwanted test commits. Clean up the history by resetting `HEAD` back to a known-good commit and force-pushing the result to the remote.

---

## Why This Matters

`git reset --hard` is one of the most destructive commands in Git — it discards commits and working-directory changes with no confirmation and no easy undo once the reflog expires. Combined with a force push, it rewrites shared history, which can silently erase other people's work if they've already pulled or based commits on what gets removed. It's the right tool for cleaning up a genuinely private mess, but on a shared branch it should only be used with the whole team's awareness.

---

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Connects to the server hosting the repository that needs its history cleaned up.

---

## Navigate to the Repository

```bash
cd /usr/kodekloudrepos/blog
```

Moves into the repository with the unwanted test commits.

---

## Review Commit History

```bash
git log --oneline
```

Identify the commit hash for the commit with message `add data.txt file`.

Lists the commit history so the last known-good commit can be identified before resetting.

---

## Reset HEAD to the Target Commit

```bash
git reset --hard <commit-hash>
```

`git reset --hard` moves `HEAD` and the `master` branch pointer back to the specified commit, discarding every commit after it and resetting the working directory to match — permanently removing the unwanted test commits from local history.

---

## Verify the History

```bash
git log --oneline
```

Confirm the history now ends at the `add data.txt file` commit.

Confirms the local branch now ends exactly where intended, with the unwanted commits gone.

---

## Force-Push the Cleaned History

```bash
git push origin master --force
```

Because the local history no longer matches what's on the remote, a normal push would be rejected — `--force` overwrites the remote branch with the local, cleaned-up history.

---

## Key Takeaways

- `git reset --hard` rewinds a branch and discards all changes after the target commit, including uncommitted work — use it carefully.
- A force push (`--force`) is required afterward because a hard reset diverges from what the remote already has.
- Rewriting shared history with reset + force-push can break other collaborators' clones; coordinate before doing this on a shared branch.
- `git log --oneline` before and after is the simplest way to confirm exactly what got removed.

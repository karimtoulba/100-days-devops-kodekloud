# Day 034 - Git Hook (post-update): Auto-Tag Releases on Push to Master

**100 Days of DevOps, Day 34:** how to write a Git `post-update` hook that automatically creates a dated release tag every time changes are pushed to `master` — a real-world Git server automation technique for CI/CD and release management.

## 🎯 Objective

Merge the `feature` branch into `master`, then create a `post-update` hook on the bare repository so that every push to `master` automatically tags a new release named `release-YYYY-MM-DD` using the current date.

---

## Why This Matters

Git hooks let a Git server react to events — commits, pushes, merges — without any external CI system. A `post-update` hook runs on the **bare (server-side) repository** after a push completes, which makes it the right place for repository-wide automation like tagging releases, triggering deployments, or notifying a chat channel. Because it lives server-side, every client that pushes benefits from it automatically — no per-developer setup required.

## Merge the Feature Branch into Master

```bash
cd /usr/kodekloudrepos/blog
sudo git checkout master
sudo git merge feature
```

- `git checkout master` switches the local working copy to the `master` branch.
- `git merge feature` brings the completed work from `feature` into `master`.

---

## Create the post-update Hook

Git hooks live in the bare repository's `hooks/` directory, not the cloned working copy:

```bash
sudo vim /opt/blog.git/hooks/post-update
```

```bash
#!/bin/sh

# Get today's date in YYYY-MM-DD format
DATE=$(date +%Y-%m-%d)
TAG_NAME="release-$DATE"

# Check if the push updated the master branch
for ref in "$@"; do
    if [ "$ref" = "refs/heads/master" ]; then
        # Ensure the tag doesn't already exist to avoid errors
        if ! git tag -l | grep -q "^$TAG_NAME$"; then
            git tag "$TAG_NAME" refs/heads/master
            echo "Successfully automated: Created release tag '$TAG_NAME' on master."
        else
            echo "Tag '$TAG_NAME' already exists. Skipping creation."
        fi
    fi
done
```

---

## Make the Hook Executable

```bash
sudo chmod +x /opt/blog.git/hooks/post-update
sudo chown natasha:natasha /opt/blog.git/hooks/post-update
```

Git silently ignores hooks that aren't executable, so this step is what actually activates the script.

---

## Test the Hook

```bash
cd /usr/kodekloudrepos/blog
sudo git push origin master
```

The push output should include:

```
Created tag: release-2026-08-23
```

---

## Verify the Release Tag

```bash
sudo git fetch --tags
```

---

## Key Takeaways

- `post-update` hooks run **server-side**, on the bare repository, after every push — not on the developer's local clone.
- A hook script must be executable (`chmod +x`) or Git will silently skip it.
- Wrapping the tag creation in an existence check makes the hook idempotent, so repeated pushes on the same day don't error out.
- This is a lightweight alternative to a full CI/CD pipeline for simple, repository-triggered automation.

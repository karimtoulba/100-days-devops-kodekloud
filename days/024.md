# Day 024 - Git Create Branches (git branch, git switch)

**100 Days of DevOps, Day 24:** how to create and switch to a new feature branch from `master` in a shared Git repository, keeping in-progress work isolated from the stable branch.

## 🎯 Objective

Create a new feature branch from `master` in an existing shared repository on the storage server.

---

## Why This Matters

Branching is what lets a team work on multiple features or fixes in parallel without one person's incomplete work breaking `master` for everyone else. Creating a feature branch before making changes — rather than committing straight to `master` — is one of the most basic but most important Git habits in any real collaborative workflow, and it's the foundation the merge and remote-management tasks in the following days build on.

---

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Logs in to the storage server hosting the shared repository.

---

## Navigate to the Repository

```bash
cd /usr/kodekloudrepos/blog
```

Moves into the working copy of the repository where the branch will be created.

---

## Switch to the Master Branch

```bash
sudo git switch master
```

Ensures the new branch is created from the current, up-to-date state of `master` rather than whatever branch happened to be checked out before.

---

## Create and Switch to the New Branch

```bash
sudo git branch xfusioncorp_blog
sudo git switch xfusioncorp_blog
```

`git branch xfusioncorp_blog` creates a new branch pointing at the current commit on `master`, and `git switch xfusioncorp_blog` checks it out so subsequent commits land on the new branch instead of `master`.

---

## Key Takeaways

- Always branch off an up-to-date `master` so the new branch starts from a known-good state.
- `git branch` creates a branch; `git switch` (or `git checkout`) is what actually moves your working tree onto it — the two are separate steps.
- Feature branches keep in-progress work isolated from `master`, so incomplete changes never risk breaking the main line.
- Naming branches after the feature or project (`xfusioncorp_blog`) makes their purpose clear to the rest of the team.

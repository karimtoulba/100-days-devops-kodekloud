# Day 013 - IPTables Installation and Configuration (yum, iptables, source IP allowlisting)

**100 Days of DevOps, Day 13:** how to install IPTables and write an ordered rule set that allows traffic to a port only from a specific trusted IP address while dropping everything else.

## 🎯 Objective

Install and configure IPTables to allow traffic from a specific IP while blocking all other access to a port.

---

## Why This Matters

IP-based allowlisting is one of the most common ways to expose an internal service (a monitoring endpoint, an admin panel, a database port) only to a known, trusted client — without needing a VPN or a full identity layer. It's also a good illustration of why rule *order* matters in IPTables: rules are evaluated top to bottom, and the first match wins, so the specific ACCEPT rule for the trusted IP has to come before the general DROP rule, or the trusted IP would be blocked along with everyone else.

---

## Install IPTables

```bash
sudo yum install iptables iptables-services -y
sudo systemctl enable --now iptables
```

Installs IPTables and its `systemd` service unit, then enables and starts the service in one step so the firewall is active immediately and persists across reboots.

---

## Configure Firewall Rules

Clear existing rules:

```bash
sudo iptables -F
```

`iptables -F` flushes all existing rules from the current chains, giving a clean slate before adding the new policy.

Allow port **8083** from a specific IP:

```bash
sudo iptables -A INPUT -p tcp -s 10.244.196.3 --dport 8083 -j ACCEPT
```

This rule accepts TCP traffic to port `8083` only when it originates from `10.244.196.3`.

Block all other traffic to port **8083**:

```bash
sudo iptables -A INPUT -p tcp --dport 8083 -j DROP
```

This second rule drops any other traffic to port `8083`. Because it's appended after the ACCEPT rule, IPTables matches the trusted IP first and only falls through to this DROP rule for every other source.

---

## Save the Rules

```bash
sudo sh -c 'iptables-save > /etc/sysconfig/iptables'
```

`iptables-save` writes the current in-memory rule set to a file so it survives a service restart or reboot instead of reverting to an empty (or default) rule set.

---

## Restart IPTables

```bash
sudo systemctl restart iptables
```

Restarting reloads the saved rule set from disk, confirming the persisted rules match what's actually active.

---

## Verify Rules

```bash
sudo iptables -L -n --line-numbers
```

Lists all active rules with numeric addresses and line numbers, making it easy to confirm both the ACCEPT and DROP rules are present and in the correct order.

---

## Key Takeaways

- IPTables evaluates rules in order and stops at the first match, so more specific ACCEPT rules must be placed before a general DROP.
- `iptables -F` clears the slate before building a new rule set — useful for avoiding conflicts with leftover rules.
- Changes made with `iptables -A` are in-memory only until `iptables-save` persists them to `/etc/sysconfig/iptables`.
- Source-IP allowlisting (`-s <ip>`) is a lightweight way to restrict a service to a single trusted client without additional authentication layers.

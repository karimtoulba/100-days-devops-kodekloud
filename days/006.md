# Day 006 - Create a Cron Job (crontab, systemctl)

**100 Days of DevOps, Day 6:** how to install `cronie`, enable the `crond` service, and schedule a recurring task with `crontab`.

## 🎯 Objective

Install the cron service, then create and manage a cron job to automate a recurring task.

---

## Why This Matters

cron is the backbone of scheduled automation on Linux — backups, log rotation, certificate renewals, and health checks all commonly run as cron jobs rather than long-running daemons. Knowing how to install the service, confirm it's actually running, and edit the crontab safely (rather than editing `/etc/crontab` by hand) is a core sysadmin skill that shows up constantly in real infrastructure work.

---

## Install Cronie

```bash
sudo yum install cronie -y
```

`cronie` is the cron daemon implementation used on RHEL/CentOS systems; it isn't always installed by default on minimal images.

---

## Start & Enable Crond / Confirm Status

```bash
sudo systemctl start crond
sudo systemctl enable crond
sudo systemctl status crond
```

Starting, enabling, and checking status in sequence confirms the cron daemon is both running now and will survive a reboot.

--

## Add New Cron Job

```bash
crontab -e
```

Add cronjob:
5 * * * * echo "Hello World!"
:wq!

`crontab -e` opens the current user's crontab in the default editor. The line `5 * * * * echo "Hello World!"` schedules the command to run at minute 5 of every hour, and `:wq!` saves and exits if the editor is vim.

---

## Validate

```bash
crontab -l
```

`crontab -l` lists the current user's scheduled jobs, confirming the new entry was saved correctly.

---

## Key Takeaways

- `cronie` provides the cron daemon on RHEL/CentOS and typically needs to be installed explicitly.
- `systemctl enable --now crond` (or the start/enable pair) ensures cron survives reboots, not just the current session.
- `crontab -e` is the safe way to edit a user's scheduled jobs; `crontab -l` verifies what's actually scheduled.
- cron's five time fields (minute, hour, day-of-month, month, day-of-week) are the foundation for any recurring Linux automation.

# Day 019 - Install and Configure Web Application (httpd, systemctl, Listen)

**100 Days of DevOps, Day 19:** how to install Apache HTTP Server, change its listening port, and deploy static application content on a Linux app server.

## 🎯 Objective

Install Apache HTTP Server, configure it on a custom port, and deploy application content.

---

## Why This Matters

Running multiple web applications on one host, or standing up a server behind a load balancer with a non-standard port mapping, requires changing Apache off its default port 80. Getting the `Listen` directive and a service restart right is a fundamental Apache/httpd skill — the same steps apply whether you're hosting a single static site or fronting several apps with different port assignments on the same box.

---

## Connect to the App Server

```bash
ssh steve@stapp02
```

Logs in to the target application server as the `steve` user, where Apache will be installed and configured.

---

## Update System Packages

```bash
yum update -y && yum upgrade -y
```

Refreshes the package index and upgrades installed packages so Apache installs against a current, patched system.

---

## Install Apache (httpd)

```bash
yum install httpd -y
```

Installs the `httpd` package — Apache's binary, default configuration, and systemd unit — non-interactively.

---

## Enable and Start Apache

```bash
systemctl enable --now httpd
```

Starts Apache immediately and enables it to launch automatically on every future boot.

---

## Configure Custom Listen Port

```bash
vim /etc/httpd/conf/httpd.conf
```

Update the `Listen` directive:

```
Listen 8083
```

Editing the `Listen` directive tells Apache to bind to port `8083` instead of the default port `80`, which matters when the host needs to run more than one web service or match a specific port expected by upstream infrastructure.

---

## Restart Apache

```bash
systemctl restart httpd
```

Apache doesn't pick up configuration file changes automatically — a restart is required to apply the new `Listen` port.

---

## Update the Default Page

```bash
vim /var/www/html/index.html
```

Edits the default document Apache serves at the site root, so a request to the server returns recognizable content instead of the stock httpd test page.

---

## Verify the Web Server

```bash
curl http://localhost:8083
```

Confirms Apache is listening and responding on the new custom port from the server itself.

---

## Deploy Application Content

```bash
sudo su
cp -r /home/thor/news /var/www/html/
cp -r /home/thor/games /var/www/html/
```

Copies the `news` and `games` application directories into Apache's document root so they become reachable as sub-paths of the site.

---

## Verify Deployed Content

```bash
curl http://localhost:8083/news/
curl http://localhost:8083/games/
```

Confirms both deployed content directories are being served correctly under the custom port.

---

## Key Takeaways

- `Listen` in `httpd.conf` controls which port Apache binds to — a config edit alone does nothing until the service is restarted.
- `systemctl enable --now` starts a service and persists it across reboots in a single command.
- Deployed content just needs to land inside the configured document root (`/var/www/html/`) to become servable.
- `curl` against `localhost` is the fastest way to sanity-check a web server before testing from outside the host.

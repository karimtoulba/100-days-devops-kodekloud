# Day 039 - Create a Docker Image From a Running Container (docker commit)

**100 Days of DevOps, Day 39:** how to snapshot a running container's current filesystem state into a brand-new Docker image using `docker commit` — a way to back up in-place changes before they're lost.

## 🎯 Objective

On the app server, create a new image named `cluster:datacenter` from the currently running container `ubuntu_latest`, preserving the changes made inside it.

---

## Why This Matters

Containers are ephemeral by design — anything changed inside one disappears when it's removed unless it's baked into an image or backed by a volume. `docker commit` captures a container's current filesystem as a new image, which is exactly what's needed when someone has made ad-hoc changes directly inside a container (installed packages, edited configs, tested a fix) and those changes need to survive beyond the container's lifetime.

---

## Connect to the App Server

```bash
ssh banner@stapp03
sudo su -
```

---

## Check the Running Container and Existing Images

```bash
docker ps -a
docker images
```

Confirms `ubuntu_latest` is the container to commit, and gives a baseline of images before the new one is created.

---

## Commit the Container to a New Image

```bash
docker commit ubuntu_latest cluster:datacenter
```

Creates a new image, `cluster:datacenter`, from the container's current filesystem state — including any files, packages, or configuration changes made since it started.

---

## Verify the New Image

```bash
docker images
```

`cluster` should now appear in the repository list with the tag `datacenter`, alongside the original base image `ubuntu_latest` was built from. Its size typically reflects the base image plus whatever changes accumulated inside the container.

---

## Key Takeaways

- `docker commit <container> <repository>:<tag>` turns a container's current state into a new, standalone image.
- This is a quick way to preserve manual, in-container changes, but it's not a substitute for a Dockerfile when changes need to be reproducible or version-controlled.
- The resulting image is independent of the source container — removing the container afterward doesn't affect the committed image.
- `docker images` is the way to confirm a commit succeeded and see how much the new image grew relative to its base.

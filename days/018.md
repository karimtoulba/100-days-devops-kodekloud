# Day 018 - Install and Configure DB Server (MariaDB, mysql, GRANT)

**100 Days of DevOps, Day 18:** how to install MariaDB on a Linux server, enable the service, and create a dedicated database, user, and privilege grant instead of using the root account for application access.

## 🎯 Objective

Install MariaDB and create a database, database user, and required privileges.

---

## Why This Matters

Applications should never connect to a database using the root MySQL/MariaDB account — a dedicated, least-privilege user scoped to a single database limits the blast radius if application credentials ever leak. This is the same pattern used to provision databases for WordPress sites, internal tools, and microservices in production: install the engine, start it as a system service, then create scoped access before anything else touches it.

---

## Switch to Root User

```bash
sudo su
```

Elevates the session to root so package installation and service management commands don't need individual `sudo` prefixes.

---

## Install MariaDB Server

```bash
yum install mariadb-server -y
```

`yum install -y` installs the MariaDB server package non-interactively, pulling in the `mariadb-server` daemon along with its default configuration.

---

## Enable and Start MariaDB

```bash
systemctl enable --now mariadb
```

`enable --now` starts the MariaDB service immediately and registers it to start automatically on every future boot, so the database survives a server restart.

---

## Access MariaDB

```bash
mysql -u root -p
```

Opens an interactive MariaDB shell as the root database user, prompting for the root password set during installation.

---

## Create Database, User, and Grant Privileges

```sql
CREATE DATABASE my_database;
CREATE USER 'my_user'@'localhost' IDENTIFIED BY 'my_secure_password';
GRANT ALL PRIVILEGES ON my_database.* TO 'my_user'@'localhost';
EXIT;
```

- `CREATE DATABASE` provisions a new, empty database for the application.
- `CREATE USER ... IDENTIFIED BY` creates a dedicated login scoped to `localhost` connections only.
- `GRANT ALL PRIVILEGES ON my_database.*` gives that user full control over just this one database — not the whole server.

---

## Key Takeaways

- MariaDB installs and manages the same way as most Linux system services: `yum install`, then `systemctl enable --now`.
- Never use the root database account for application connections — create a scoped user instead.
- `GRANT ... ON database.*` limits privileges to a single database, following the principle of least privilege.
- Restricting the user to `'my_user'@'localhost'` prevents remote logins with that account entirely.

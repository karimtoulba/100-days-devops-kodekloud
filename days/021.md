# Day 021 - Set Up Git Repository on Storage Server (git init --bare)

**100 Days of DevOps, Day 21:** how to install Git on a Linux server and initialize a bare repository — the central, push/pull-only repo a development team clones and pushes to.

## 🎯 Objective

Install Git on the storage server and create a bare Git repository with proper ownership for use by the development team.

---

## Why This Matters

A bare repository has no working directory — it stores only Git's internal history, refs, and objects, and exists purely to be a shared push/pull target. This is exactly how a self-hosted Git server (or the storage layer behind GitHub/GitLab/Gitea) is structured: developers never work directly inside a bare repo, they clone it, make changes locally, and push back. Getting this foundational layout right is what every later branching, merging, and remote-management task in a Git workflow builds on top of.

---

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Logs in to the dedicated storage server that will host the team's shared Git repositories.

---

## Install Git

```bash
sudo yum install git -y
```

Installs the Git package non-interactively via `yum`.

---

## Verify Installation

```bash
git --version
```

Confirms Git installed successfully and reports the installed version.

---

## Create the Repository Directory

```bash
sudo mkdir -p /opt/beta.git
cd /opt/beta.git
```

Creates the directory that will hold the bare repository, using the `.git` suffix convention that signals "this is a bare repo, not a working copy."

---

## Initialize a Bare Repository

```bash
sudo git init --bare
```

`git init --bare` creates a repository with no working directory — only the Git object database and refs — making it suitable as a central location developers push to and pull from, rather than edit directly.

---

## Key Takeaways

- A bare repository (`git init --bare`) has no working tree — it's storage and a push/pull target only.
- The `.git` suffix on the directory name is the standard convention for identifying a bare repo at a glance.
- This is the same underlying structure used by self-hosted Git servers like Gitea, GitLab, and Bitbucket.
- Installing Git and verifying the version before creating repositories is good practice to catch environment issues early.

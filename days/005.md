# Day 005 - SELinux Installation and Configuration (sestatus, getenforce)

**100 Days of DevOps, Day 5:** how to install SELinux tooling, inspect its current status with `sestatus` and `getenforce`, and set its operating mode persistently.

## 🎯 Objective

Install SELinux tools, check the current SELinux status, and configure its operating mode.

---

## Why This Matters

SELinux (Security-Enhanced Linux) adds mandatory access control on top of standard Linux file permissions, restricting what a process can do even if it's running as root. It's a common source of confusing, hard-to-diagnose "permission denied" errors on RHEL/CentOS systems when a service is correctly configured but SELinux policy still blocks it — which is why understanding how to check its mode and status, rather than reflexively disabling it, is an important production skill.

---

## Install SELinux Tools

```bash
sudo yum update && sudo yum upgrade -y
sudo yum install selinux-basics selinux-utils policycoreutils -y
```

This updates the system and installs the core SELinux packages, including `policycoreutils`, which provides the everyday SELinux management commands.

---

## Check SELinux Status

```bash
sestatus
```

`sestatus` reports whether SELinux is enabled, which mode it's running in, and which policy is loaded.

---

## View Current Mode

```bash
getenforce
```

`getenforce` is a quick one-word check of the current mode: `Enforcing`, `Permissive`, or `Disabled`.

---

## Configure SELinux Mode (Persistent)

Edit the configuration file:

```bash
sudo nano /etc/selinux/config
```

Example:

```text
SELINUX=enforcing
```

Editing `/etc/selinux/config` changes the mode that persists across reboots — `enforcing` actively blocks and logs policy violations, `permissive` only logs them, and `disabled` turns SELinux off entirely.

---

## Key Takeaways

- SELinux enforces mandatory access control beyond standard file permissions, even for root.
- `sestatus` and `getenforce` are the go-to commands for checking SELinux state before troubleshooting.
- Mode changes made in `/etc/selinux/config` require a reboot (or `setenforce` for a temporary runtime change) to take effect.
- Disabling SELinux outright is a common but risky shortcut — `permissive` mode is a safer way to diagnose policy issues without losing the audit trail.

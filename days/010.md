# Day 010 - Linux Bash Scripts (bash, zip, scp, cron-ready)

**100 Days of DevOps, Day 10:** how to write a Bash script that automates backing up a website directory into a ZIP archive and shipping it to a remote backup server over passwordless SSH.

## 🎯 Objective

Create a Bash script to back up a website directory, compress it into a ZIP archive, and copy it to a remote backup server using passwordless SSH.

---

## Why This Matters

Manual backups get forgotten; scripted backups don't. Wrapping the backup steps — compress, transfer — into a single reusable script is what makes a backup routine reliable enough to schedule with `cron` and safe enough to hand off to another engineer. Passwordless SSH (key-based auth) is what lets the script run unattended, without a human typing a password every time it fires, which is essential for any automated or scheduled job.

---

## Create the Script

```bash
sudo mkdir -p /scripts
sudo nano /scripts/ecommerce_backup.sh
```

Add:

```bash
#!/bin/bash

SRC_DIR="/var/www/html/ecommerce"
BACKUP_DIR="/backup"
ARCHIVE="xfusioncorp_ecommerce.zip"
REMOTE_USER="clint"
REMOTE_HOST="stbkp01"
REMOTE_DIR="/backup"

zip -r "$BACKUP_DIR/$ARCHIVE" "$SRC_DIR"
scp "$BACKUP_DIR/$ARCHIVE" "$REMOTE_USER@$REMOTE_HOST:$REMOTE_DIR/"
```

The script defines the source directory, backup destination, and remote connection details as variables up top, then `zip -r` compresses the website directory into an archive and `scp` copies that archive to the backup server — all driven by those variables, so the script is easy to reuse for other directories or hosts.

---

## Make the Script Executable

```bash
chmod +x /scripts/ecommerce_backup.sh
```

`chmod +x` marks the script as executable so it can be run directly (`./ecommerce_backup.sh`) or invoked by `cron` without needing `bash script.sh`.

---

## Run the Script

```bash
/scripts/ecommerce_backup.sh
```

Running the script by its full path executes the backup end-to-end — compressing the site directory and pushing the archive to the remote backup server in one step.

---

## Verify the Backup

Local:

```bash
ls -lh /backup
```

Remote:

```bash
ssh clint@stbkp01
ls -lh /backup
```

Checking both the local `/backup` directory and the remote server confirms the entire pipeline worked — the archive was created locally and successfully transferred over SSH.

---

## Key Takeaways

- Wrapping backup and transfer logic in a single Bash script turns a manual, error-prone task into a repeatable, schedulable one.
- Passwordless (key-based) SSH is what makes unattended, scripted transfers possible.
- `zip -r` for compression and `scp` for transfer is a lightweight, dependency-free backup pattern that works on almost any Linux box.
- Verifying on both ends (source and destination) is the only way to be sure a backup actually completed successfully.

# Day 003 - Secure Root SSH Access (sshd_config, PermitRootLogin)

**100 Days of DevOps, Day 3:** how to disable direct root SSH login by editing `sshd_config`, forcing administration through a regular user account with `sudo` instead.

## 🎯 Objective

Disable direct root SSH login and require administration through a regular user account with `sudo`, then verify the change is enforced.

---

## Why This Matters

Allowing direct root SSH login is one of the most common findings in a Linux security audit. It removes any per-user audit trail (every root action looks identical in the logs), and it turns the `root` password into a single point of failure for brute-force attacks, since `root` is a known, guessable username on every Linux box. Forcing admins through a named account with `sudo` keeps a record of who ran what, and lets access be revoked per-user instead of by rotating a shared root password.

---

## Check Root Login Status

```bash
cat /etc/ssh/sshd_config | grep PermitRootLogin
```

This confirms the current `PermitRootLogin` setting before making any change, so you know the starting state.

---

## Disable Root SSH Login

Edit the SSH configuration:

```bash
sudo vim /etc/ssh/sshd_config
```

Set:

```text
PermitRootLogin no
```

Setting `PermitRootLogin no` tells the SSH daemon to reject any login attempt that uses the `root` account directly, regardless of whether the correct password or key is supplied.

---

## Restart SSH Service

Ubuntu:

```bash
sudo systemctl restart ssh
```

RHEL/CentOS:

```bash
sudo systemctl restart sshd
```

SSH config changes only take effect after the daemon is restarted (the exact service name differs between Ubuntu's `ssh` and RHEL/CentOS's `sshd`), so this step is required before the new policy is enforced.

---

## Test SSH Access

Try logging in as root:

```bash
ssh root@<server-ip>
```

Expected result:

```text
Permission denied.
```

A rejected root login confirms the policy is active. From here on, administrators must log in as their own user and use `sudo` for privileged commands.

---

## Key Takeaways

- `PermitRootLogin no` in `sshd_config` is a baseline hardening step for any internet-facing Linux server.
- SSH config changes require a service restart (`sshd` on RHEL/CentOS, `ssh` on Ubuntu/Debian) before they take effect.
- Disabling root login forces all administration through named accounts with `sudo`, which preserves an audit trail.
- Always keep a working non-root, sudo-capable session open while testing this change, to avoid locking yourself out.

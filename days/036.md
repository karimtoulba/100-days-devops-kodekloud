# Day 036 - Deploy Nginx Container on Application Server (docker run, docker pull)

**100 Days of DevOps, Day 36:** how to pull the lightweight `nginx:alpine` image and run it as a named, detached Docker container — the first hands-on container deployment of the Container Fundamentals track.

## 🎯 Objective

On the app server, pull the `nginx:alpine` image and run it as a container named `nginx_3`, then confirm it's in a running state.

---

## Why This Matters

Running a container by name (`--name nginx_3`) instead of relying on Docker's auto-generated names makes it predictable to reference in later commands — `docker logs`, `docker exec`, `docker stop` — which matters once you're managing more than one container on a host. The `alpine` tag is also a deliberate choice: Alpine-based images are a fraction of the size of the default Nginx image, which means faster pulls and a smaller attack surface — a pattern worth carrying into every container you deploy.

---

## Connect to the App Server

```bash
ssh banner@stapp03
```

---

## Pull the Nginx Alpine Image

```bash
docker pull nginx:alpine
```

Pulls the lightweight, Alpine Linux–based Nginx image from Docker Hub. Alpine images are commonly a fraction the size of their Debian/Ubuntu-based counterparts.

---

## Run the Container

```bash
docker run -d --name nginx_3 nginx:alpine
```

- `-d` runs the container detached, in the background.
- `--name nginx_3` gives the container a fixed, predictable name instead of a random one.

---

## Verify the Container Is Running

```bash
docker ps -a
```

Look for `nginx_3` in the output with a status of `Up`:

```
CONTAINER ID   IMAGE          COMMAND                  STATUS         NAMES
xxxxxxxxxxxx   nginx:alpine   "/docker-entrypoint.…"   Up X seconds   nginx_3
```

`docker ps -a` lists all containers, including stopped ones, so you can confirm the container both exists and is currently running.

---

## Key Takeaways

- `docker pull` and `docker run` are the two core commands for getting any container image running locally.
- Naming containers explicitly (`--name`) makes them easier to manage once you're running more than one.
- Alpine-tagged images are a quick win for smaller, faster-to-pull containers.
- `docker ps -a` (not just `docker ps`) is the reliable way to check container state, since it also surfaces containers that exited unexpectedly.

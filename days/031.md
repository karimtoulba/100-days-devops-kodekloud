# Day 031 - Git Stash (git stash list, git stash apply)

**100 Days of DevOps, Day 31:** how to inspect multiple stashed changesets with `git stash list` and restore a specific one with `git stash apply stash@{n}`, without disturbing other stashes.

## 🎯 Objective

A developer stashed some in-progress changes in the repository but only wants to restore one specific stash. Locate and restore it, then commit and push the changes.

---

## Why This Matters

`git stash` is the standard way to set aside uncommitted work temporarily — to switch branches, pull updates, or context-switch — without committing half-finished changes. Once multiple stashes pile up, it's easy to apply or drop the wrong one if you're not careful about indexing (`stash@{0}` is always the most recent). Knowing how to list, inspect, and selectively restore a specific stash avoids losing or overwriting other in-progress work sitting in the stash stack.

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Connects to the server hosting the repository with the stashed changes.

---

## Navigate to the Repository

```bash
cd /usr/kodekloudrepos/blog
```

Moves into the repository where the stashes were created.

---

## List the Stashed Changes

```bash
git stash list
```

`git stash list` shows every stash currently saved, each labeled with an index like `stash@{0}`, `stash@{1}`, in order from most to least recent.

---

## Inspect the Target Stash

```bash
git stash list
```

Re-running the list (optionally with `git stash show stash@{1}` in practice) confirms which index corresponds to the specific changeset that needs to be restored.

---

## Restore the Specific Stash

```bash
git stash apply stash@{1}
```

`git stash apply stash@{1}` restores only that specific stash's changes into the working directory, leaving the stash itself (and any other stashes) intact in the stash list.

---

## Stage and Commit the Restored Changes

```bash
git add .
git commit -m "Restore stashed changes from stash@{1}"
```

Stages and commits the restored changes so they become a permanent part of the branch's history.

---

## Push the Changes

```bash
git push origin master
```

Publishes the commit containing the restored changes to the remote repository.

---

## Key Takeaways

- `git stash list` shows all saved stashes with their index, letting you target a specific one instead of just the most recent.
- `git stash apply stash@{n}` restores a named stash without removing it from the stash list (unlike `git stash pop`, which removes it after applying).
- Stash indexes shift as new stashes are added, so it's worth double-checking `git stash list` right before applying.
- Restored changes still need to be staged and committed like any other change — stashing doesn't commit anything automatically.

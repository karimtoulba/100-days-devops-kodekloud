# Day 020 - Configure Nginx + PHP-FPM Using Unix Sock (nginx, php-fpm, fastcgi_pass)

**100 Days of DevOps, Day 20:** how to wire Nginx and PHP-FPM together over a Unix domain socket instead of TCP, then serve a PHP application through the combination.

## 🎯 Objective

Install and configure Nginx and PHP-FPM to communicate over a Unix socket, then deploy a PHP-based application.

---

## Why This Matters

Nginx has no built-in PHP interpreter, so it hands `.php` requests off to PHP-FPM over FastCGI. A Unix socket is the preferred transport for that hand-off on a single host — it skips the TCP/IP stack entirely, which is faster and avoids exposing PHP-FPM on a network port that doesn't need to be reachable at all. Getting file ownership and socket permissions right between the two services is the most common source of "502 Bad Gateway" errors in real Nginx + PHP deployments.

```bash
ssh banner@stapp03
```

Logs in to the app server where Nginx and PHP-FPM will be installed and connected.

## Install Nginx

```bash
sudo yum install nginx -y
```

Installs the Nginx web server package, which will act as the reverse proxy in front of PHP-FPM.

---

## Install PHP-FPM

```bash
sudo dnf update -y sudo dnf upgrade -y
sudo dnf install -y epel-release
sudo dnf install -y http://rpms.remirepo.net/enterprise/remi-release-$(rpm -E %rhel).rpm
sudo dnf install -y dnf-utils
```

Adds the EPEL and Remi repositories, since the specific PHP-FPM version needed isn't available in the base RHEL/CentOS repos, and installs `dnf-utils` for module management.

---

## Install PHP 8.2-FPM

```bash
dnf module reset php
dnf module install php:remi-8.1
dnf install php-fpm -y
php -v
```

Resets any existing PHP module stream, switches to the Remi-provided PHP 8.1 stream, installs the `php-fpm` package, and confirms the installed version.

---

## Configure PHP-FPM to Use a Unix Socket

```bash
sudo vim /etc/php-fpm.d/www.conf
```

Update the `listen` directive and ownership:

```
user = nginx
group = nginx
listen = /var/run/php-fpm/default.sock
listen.owner = nginx
listen.group = nginx
listen.mode = 0660
```

Sets PHP-FPM's pool to run as the `nginx` user/group and listen on a Unix socket file rather than a TCP port, with permissions (`0660`) that let the Nginx process — and only that process — read and write to it.

---

## Configure Nginx to Listen on Custom Port

```bash
sudo vim /etc/nginx/nginx.conf
```

Update the `server` block:

```nginx
server {
    listen 8095;
    root /var/www/html;
    index index.php index.html index.htm;

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/var/run/php-fpm/default.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

The `location ~ \.php$` block is the piece that actually connects the two services: any request for a `.php` file is passed to PHP-FPM over the same Unix socket path configured in `www.conf`, with `fastcgi_param SCRIPT_FILENAME` telling PHP-FPM exactly which script to execute.

---

## Start/Enable Nginx and PHP-FPM

```bash
sudo systemctl enable --now nginx
sudo systemctl enable --now php-fpm
```

Starts both services and enables them to launch automatically on boot — both must be running for PHP requests to resolve correctly.

---

## Verify the Web Server

```bash
curl http://stapp03:8095/index.php
```

Confirms Nginx is serving on the custom port and successfully proxying `.php` requests to PHP-FPM through the socket.

---

## Key Takeaways

- Nginx delegates PHP execution to PHP-FPM over FastCGI — it never interprets PHP itself.
- A Unix socket is faster and more secure than TCP for same-host Nginx/PHP-FPM communication, since it never touches the network stack.
- The `listen.owner`/`listen.group`/`listen.mode` settings in `www.conf` must match what Nginx runs as, or requests fail with permission errors.
- `fastcgi_pass` in the Nginx `location` block and `listen` in `www.conf` must point at the exact same socket path.

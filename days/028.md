# Day 028 - Git Cherry Pick (git cherry-pick)

**100 Days of DevOps, Day 28:** how to use `git cherry-pick` to apply a single commit from one branch onto another, without merging the rest of the source branch's history.

## 🎯 Objective

A developer working on the `feature` branch has a single commit that needs to be applied to `master` without merging the entire branch. Use `git cherry-pick` to bring over just that commit.

---

## Why This Matters

Merging an entire branch just to grab one useful commit drags in unrelated, possibly unfinished work. `git cherry-pick` solves this by replaying a single commit's changes onto the current branch as a brand-new commit, which is exactly the tool for hotfixes, backporting a fix to a release branch, or pulling one specific change out of a larger feature branch that isn't ready to be merged wholesale.

## Connect to the Storage Server

```bash
ssh natasha@ststor01
```

Connects to the server hosting the repository.

---

## Navigate to the Repository

```bash
cd /usr/kodekloudrepos/blog
```

Moves into the repository containing both the `feature` and `master` branches.

---

## Find the Commit on the Feature Branch

```bash
git switch feature
git log --oneline
```

Locate the commit hash for the commit with message `Update info.txt`.

Switches to `feature` and lists its commit history so the exact commit hash to cherry-pick can be identified.

---

## Switch to Master

```bash
git switch master
```

Moves back to `master`, the branch the commit will be applied onto.

---

## Cherry-Pick the Commit

```bash
git cherry-pick <commit-hash>
```

Replays only the changes from the specified commit onto `master`, creating a new commit with the same changes (and a new hash) — without bringing in any other commits from `feature`.

---

## Verify the Commit Was Applied

```bash
git log --oneline
```

Confirms the cherry-picked commit now appears at the top of `master`'s history.

---

## Push the Changes

```bash
git push origin master
```

Publishes the updated `master` branch, including the cherry-picked commit, to the remote.

---

## Key Takeaways

- `git cherry-pick <hash>` applies one specific commit's changes to the current branch as a new commit.
- It's the right tool when you need a single fix or change without merging an entire branch's history.
- The cherry-picked commit gets a new hash on the target branch — it's a copy of the changes, not a move.
- Commonly used for hotfixes and backporting fixes to release or maintenance branches.

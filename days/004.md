# Day 004 - Script Execution Permissions (chmod +x)

**100 Days of DevOps, Day 4:** how Linux file permission bits control whether a shell script can run directly, and how to grant execute permission with `chmod +x`.

## 🎯 Objective

Learn how to make a shell script executable and manage its execution permissions using `chmod`.

---

## Why This Matters

Every script created on Linux starts out without execute permission, which is a deliberate safety default — you shouldn't be able to accidentally run a file just because it exists in your path. Understanding `chmod` and the read/write/execute bits is fundamental to Linux administration: it's the same permission model behind securing config files, locking down deployment scripts, and troubleshooting the classic "Permission denied" error every DevOps engineer hits early on.

---

## Create a Script

```bash
vim script.sh
```

Add:

```bash
#!/bin/bash
echo "Hello, DevOps!"
```

The `#!/bin/bash` shebang line tells the shell which interpreter to run the script with, and the `echo` command prints a simple message when the script executes.

---

## Check Permissions

```bash
ls -la hello.sh
```

`ls -la` lists the file's permission bits. A freshly created script typically shows `-rw-r--r--` — read and write, but no execute permission for anyone, including the owner.

---

## Make the Script Executable

```bash
chmod +x hello.sh
```

`chmod +x` adds the execute bit for the owner, group, and others, so the file can now be run directly rather than only read.

---

## Run the Script

```bash
./hello.sh
```

Expected output:

```text
Hello, DevOps!
```

Running the script with `./hello.sh` works because the execute bit is now set and the shebang line points the shell at the correct interpreter.

---

## Key Takeaways

- New files on Linux never have execute permission by default — it must be granted explicitly.
- `chmod +x <file>` is the standard way to make a script runnable.
- `ls -la` is the quickest way to inspect a file's current permission bits before troubleshooting a "Permission denied" error.
- The `#!/bin/bash` shebang line determines which interpreter actually runs the script.

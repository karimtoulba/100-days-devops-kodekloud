# Day 015 - Setup SSL for Nginx (yum, systemctl, nginx.conf, iptables)

**100 Days of DevOps, Day 15:** how to install Nginx, install an SSL certificate and private key, configure Nginx to serve HTTPS on port 443, and open both HTTP and HTTPS through the firewall.

## 🎯 Objective

Install Nginx, configure HTTPS using an SSL certificate, and allow HTTP/HTTPS through the firewall.

---

## Why This Matters

Serving a site over plain HTTP means every request — including any credentials or session data — travels the network in plaintext, readable to anyone positioned to intercept it. Terminating TLS at Nginx is one of the most common patterns in production: the certificate and private key live on the web/proxy tier, permissions on the key file are locked down to prevent unauthorized reads, and the firewall is opened for both port 80 (often used to redirect to HTTPS) and port 443 (the actual encrypted traffic). Getting file permissions and the certificate/key paths right is what separates a working HTTPS setup from a silent misconfiguration.

---

## Install Nginx

```bash
sudo yum install nginx iproute iptables -y
sudo systemctl enable --now nginx
```

Installs Nginx along with `iproute` (for `ss`) and `iptables`, then starts Nginx and enables it to persist across reboots.

---

## Verify the Service

```bash
ss -tulnp
```

Confirms Nginx is up and shows which port it's currently listening on.

---

## Create a Test Page

```bash
echo "Welcome!" > /usr/share/nginx/html/index.html
```

Test:

```bash
curl http://stapp01
```

Writes a simple test page to Nginx's default document root, then uses `curl` to confirm the web server responds over plain HTTP before adding TLS on top.

---

## Install the SSL Certificate

```bash
sudo chmod 600 /tmp/nautilus.crt
sudo chmod 600 /tmp/nautilus.key

sudo cp /tmp/nautilus.crt /etc/pki/tls/certs/nautilus.crt
sudo cp /tmp/nautilus.key /etc/pki/tls/private/nautilus.key
```

`chmod 600` restricts the certificate and private key so only the owner can read them, then both files are copied into the standard system locations for TLS certificates (`certs/`) and private keys (`private/`) so Nginx can reference them.

---

## Configure Nginx

Edit the configuration:

```bash
sudo vim /etc/nginx/nginx.conf
```

Configure the server to listen on **443** and reference:

- `/etc/pki/tls/certs/nautilus.crt`
- `/etc/pki/tls/private/nautilus.key`

This adds (or updates) a `server` block that listens on port `443` with `ssl` enabled, pointing `ssl_certificate` and `ssl_certificate_key` at the files copied in the previous step — the core directives that turn on HTTPS termination in Nginx.

---

## Allow HTTP and HTTPS

```bash
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

sudo sh -c 'iptables-save > /etc/sysconfig/iptables'
```

Opens both port 80 (HTTP) and port 443 (HTTPS) in the firewall, then persists the rules so they survive a restart or reboot.

---

## Key Takeaways

- TLS termination at Nginx is a standard production pattern for encrypting traffic between clients and the web/proxy tier.
- Private keys should always be locked down with restrictive permissions (`chmod 600`) — a world-readable key defeats the purpose of encryption.
- Certificates and keys belong in the standard system paths (`/etc/pki/tls/certs`, `/etc/pki/tls/private`) so Nginx and other tools can find them predictably.
- Both HTTP and HTTPS ports typically need firewall access — HTTP for redirects or health checks, HTTPS for the actual encrypted traffic.

# Day 011 - Install and Configure Tomcat Server (yum, systemctl, server.xml)

**100 Days of DevOps, Day 11:** how to install Apache Tomcat, enable it as a persistent service, and reconfigure its listening port by editing `server.xml`.

## 🎯 Objective

Install Apache Tomcat, configure the service, and verify that it is running.

---

## Why This Matters

Tomcat is the de facto standard servlet container for Java web applications, so knowing how to install it, keep it running across reboots, and repoint its listener to a non-default port is a recurring task in any Java-based DevOps environment. Getting the port configuration right in `server.xml` matters because a misconfigured `Connector` block is one of the most common reasons a freshly installed Tomcat instance appears "up" in `systemctl status` but is unreachable from outside.

---

## Install Tomcat

```bash
sudo yum install tomcat -y
```

Installs Apache Tomcat and its dependencies from the system's `yum` repositories.

---

## Enable and Start the Service

```bash
sudo systemctl start tomcat
sudo systemctl enable tomcat
```

`start` brings Tomcat up immediately, and `enable` registers it with `systemd` so it starts automatically on every future boot.

---

## Verify the Service Status

```bash
sudo systemctl status tomcat
```

Confirms the service is active and running before moving on to configuration changes.

---

## Update Tomcat Listening Port

```bash
sudo vim /etc/tomcat/server.xml
```

Update "Connector" to 8080
:wq!

Tomcat's HTTP listener is defined by a `Connector` element in `server.xml`; changing its `port` attribute to `8080` and saving (`:wq!`) is how the service is pointed at the port the application is expected to answer on.

---

## Test the Web Server

```bash
curl http://localhost:8080
```

A successful response confirms Tomcat is listening on the newly configured port and serving requests.

---

## Key Takeaways

- `yum install tomcat` plus `systemctl enable --now`-style commands is the standard pattern for getting a Java servlet container running as a managed service.
- Tomcat's listening port is controlled by the `Connector` element in `server.xml`, not a command-line flag.
- Always restart/verify after editing `server.xml`, since a bad connector edit can leave the service running but unreachable.
- `curl` against the configured port is the fastest way to confirm the whole chain — install, service, and config — actually works end to end.

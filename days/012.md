# Day 012 - Linux Network Services (ss, systemctl, iptables)

**100 Days of DevOps, Day 12:** how to audit listening network services, swap a conflicting service for the one actually needed, and open a firewall port with `iptables` to allow web traffic through.

## 🎯 Objective

Manage Linux network services and configure firewall rules to allow web traffic.

---

## Why This Matters

On a fresh or unfamiliar server, it's common to find an unrelated service (like Sendmail) either idle or unexpectedly bound to a port a web application needs. Knowing how to inspect listening sockets, cleanly stop and disable a service you don't need, and then open exactly the port required — no more, no less — is core Linux network administration and a direct application of the principle of least privilege at the firewall level.

---

## Check Listening Services

```bash
ss -tulnp | grep 8080
```

`ss -tulnp` lists all TCP/UDP sockets currently listening, along with the owning process, so you can see immediately whether anything is already using port `8080`.

---

## Stop and Disable Sendmail

```bash
sudo systemctl stop sendmail
sudo systemctl disable sendmail
```

`stop` shuts Sendmail down right away, and `disable` prevents it from starting again on the next boot, freeing up the resources (and potentially the port) it was holding.

---

## Start and Enable Apache

```bash
sudo systemctl start httpd
sudo systemctl enable httpd
```

Starts the Apache (`httpd`) web server and enables it so it persists across reboots — the service actually meant to be serving web traffic on this host.

---

## Allow Port 8080 Through the Firewall

```bash
sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
sudo systemctl restart iptables
```

`iptables -I INPUT` inserts a rule at the top of the `INPUT` chain accepting TCP traffic on port `8080`, and restarting the `iptables` service reloads the rule set so the new rule takes effect immediately.

---

## Verify

```bash
sudo iptables -L
ss -tulnp | grep 8080
```

`iptables -L` confirms the ACCEPT rule is in place, and `ss -tulnp` confirms Apache is now the process actually listening on port `8080`.

---

## Key Takeaways

- `ss -tulnp` is the go-to command for seeing what's actually listening on a port before troubleshooting further.
- Disabling an unneeded service (not just stopping it) prevents it from silently coming back after a reboot.
- `iptables -I` inserts a rule at the top of the chain, which matters when rule order determines whether traffic is accepted or dropped.
- Firewall changes should always be verified with both the firewall's own listing (`iptables -L`) and an independent check (`ss`) of the actual socket state.

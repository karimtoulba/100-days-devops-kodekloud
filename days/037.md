# Day 037 - Copy File to Docker Container (docker cp)

**100 Days of DevOps, Day 37:** how to copy a file from a Docker host into a running container's filesystem using `docker cp`, without altering the file's contents — a core Container Fundamentals skill.

## 🎯 Objective

On the app server, copy the encrypted file `/tmp/nautilus.txt.gpg` from the Docker host into the `/home/` directory of the running container `ubuntu_latest`, without modifying the file in any way.

---

## Why This Matters

`docker cp` moves files between the host and a container without needing SSH, a shared volume, or the container even having networking configured — which makes it the fastest way to get a single file (a config, a cert, a data dump) into or out of a running container. Because it works at the filesystem level, it preserves file contents exactly, which matters here since the `.gpg` extension means the file is encrypted — any corruption during transfer would make it unrecoverable.

---

## Connect to the App Server

```bash
ssh steve@stapp02
```

---

## Check the Running Container

```bash
sudo su -
docker ps -a
```

Confirms the container is named `ubuntu_latest` and currently running before attempting the copy.

---

## Copy the File into the Container

```bash
docker cp /tmp/nautilus.txt.gpg ubuntu_latest:/home/
```

- The source is a path on the Docker host (`/tmp/nautilus.txt.gpg`).
- The destination uses `<container>:<path>` syntax to target a directory inside the running container.

---

## Verify the File Was Copied

```bash
docker exec ubuntu_latest ls -ltr /home/
```

The file should appear at `/home/nautilus.txt.gpg` with the same size and content as the original — `docker exec` runs the `ls` command inside the container to confirm without needing a shell into it.

---

## Key Takeaways

- `docker cp` copies files directly between the host and a container's filesystem — no volume mount or network access required.
- The `<container>:<path>` destination syntax is what tells Docker to target the container's filesystem rather than the host's.
- `docker exec <container> <command>` is a quick way to run a one-off verification command inside a container without opening an interactive shell.
- Copying binary/encrypted files works safely because `docker cp` is a byte-for-byte transfer, not a text operation.

# Day 029 - Manage Git Pull Requests (Gitea, code review workflow)

**100 Days of DevOps, Day 29:** how to run a full code-review workflow in Gitea — opening a Pull Request as one user, assigning a reviewer, and approving and merging it as another — instead of pushing straight to `master`.

## 🎯 Objective

Merge code into `master` using a reviewed Pull Request instead of pushing directly. Create the PR as `max`, assign `tom` as reviewer, then review and merge it as `tom`.

---

## Why This Matters

Pushing directly to a shared branch like `master` skips the one safeguard that catches mistakes before they ship: another set of eyes. Pull Request workflows — used in every mainstream Git hosting platform, including self-hosted Gitea — enforce that changes are reviewed, discussed, and explicitly approved before they land. This is the backbone of team collaboration in real DevOps environments and is usually paired with branch protection rules that make direct pushes to `master` impossible entirely.

## Create the Pull Request

1. Open the repository in Gitea.
2. Switch to the `story/fox-and-grapes` branch.
3. Click **New Pull Request**, comparing `story/fox-and-grapes` into `master`.
4. Add a title/description for the PR.
5. Assign **tom** as the reviewer.
6. Submit the pull request.

Opening the PR as `max` and explicitly assigning `tom` as reviewer models a real team workflow where the author cannot approve their own change.

---

## Log In as Tom

```
Username: tom
Password: Tom_pass123
```

Switches to the reviewer's account, since only `tom` was assigned to review this PR.

---

## Review and Merge the Pull Request

1. Open the **Pull Requests** tab.
2. Open the PR submitted by Max.
3. Review the changes and add a comment.
4. Approve the review.
5. Click **Merge Pull Request**.

`tom` inspects the diff, leaves feedback, and only merges after explicitly approving — the core discipline a PR workflow is meant to enforce.

---

## Verify the Merge

Confirm the `story/fox-and-grapes` branch changes now appear in `master`.

---

## Key Takeaways

- Pull Requests add a review gate between a developer's branch and the shared `master` branch.
- Assigning a specific reviewer and requiring their approval before merge is standard practice on real engineering teams.
- Gitea provides the same core PR workflow as GitHub/GitLab, making it a solid self-hosted alternative to learn.
- Merging via the UI (rather than a raw `git push`) keeps the review, comments, and approval history attached to the change permanently.

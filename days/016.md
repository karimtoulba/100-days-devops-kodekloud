# Day 016 - Install and Configure Nginx as an LBR (yum, upstream, proxy_pass)

**100 Days of DevOps, Day 16:** how to configure Nginx as a Layer 7 load balancer, using an `upstream` block and `proxy_pass` to distribute HTTP requests across multiple application servers.

## 🎯 Objective

Install Nginx and configure it as a Layer 7 Load Balancer to distribute HTTP traffic across multiple application servers.

---

## Why This Matters

A single application server is a single point of failure and a hard ceiling on throughput. Putting Nginx in front of a pool of identical app servers — load balancing traffic across them — is one of the most common patterns in production web architecture: it enables horizontal scaling, lets individual backend servers be patched or restarted without downtime, and gives you one place to enforce things like headers, rate limiting, or TLS termination for the whole fleet.

---

## Install Nginx

```bash
sudo yum install nginx -y
```

Installs Nginx on the load balancer host.

---

## Check Application Server Ports

Connect to an application server:

```bash
ssh tony@stapp01
sudo su
ss -tulnp
```

Identify the HTTP port used by the application servers.

Before writing the load balancer config, it's necessary to confirm which port the backend application actually listens on — here, port `3001` — so the `upstream` block points at the right target.

---

## Configure Nginx

```bash
sudo vim /etc/nginx/nginx.conf
```

Add the backend server pool:

```nginx
upstream backend_servers {
    server stapp01:3001;
    server stapp02:3001;
    server stapp03:3001;
}

server {
    listen 80;
    server_name localhost;

    location / {
        proxy_pass http://backend_servers;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

The `upstream backend_servers` block defines the pool of application servers Nginx will balance traffic across (each on port `3001`), and the `server` block listens on port `80` and uses `proxy_pass` to forward every request to that pool. The `proxy_set_header` directives preserve the original `Host`, client IP, and forwarding chain so the backend servers can see the real client information instead of just seeing the load balancer.

---

## Enable and Start Nginx

```bash
sudo systemctl enable --now nginx
```

Starts Nginx immediately and enables it to persist across reboots, activating the load balancer configuration.

---

## Verify

```bash
sudo systemctl status nginx
curl http://stlb01:80
```

Confirms the service is running, and `curl` against the load balancer's hostname verifies it's actually proxying requests through to one of the backend application servers.

---

## Key Takeaways

- Nginx can act as a Layer 7 (HTTP-aware) load balancer using nothing more than `upstream` and `proxy_pass` — no separate load balancer product required.
- Always confirm the backend port the application actually listens on before wiring up the `upstream` block.
- Forwarding headers (`Host`, `X-Real-IP`, `X-Forwarded-For`) matter — without them, backend servers lose visibility into the real client and original request details.
- Verifying through the load balancer's own address (not the backend servers directly) is what actually proves the proxy path works end to end.
